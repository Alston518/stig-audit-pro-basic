Basic App Check Setup Worksheet

What this is: An editable worksheet for every implemented IOS and IOS-XE L2 and NDM check. It tells you what the app looks for, whether you must enter a site value, where that value goes, and what evidence to review.

What this is not: A completed CKL or an approval decision. Confirm results against your current benchmark, device evidence, and site policy. The separate Complete Check Reference gives the exact expressions and all decision details.

How to use this worksheet

Keep this Word file as your working copy. Search a V number with Ctrl+F, then replace each [enter …] prompt with the approved value or reviewer note.

On the Audit tab, choose IOS or IOS XE, L2 or NDM (or both), and the site profile. Live SSH requires the target addresses and SSH credentials. Those connection inputs apply to the whole audit and are not repeated under every check.

For each check marked “Site values required”, its card below names the exact YAML field and default file. IOS uses Application\data\profiles\base_ios_switch_access.yaml; IOS XE uses Application\data\profiles\base_iosxe_access.yaml. If Audit selects a different profile, edit that selected file instead. Close and reopen the app after adding or renaming profiles. Preserve YAML indentation and list syntax.

“No site value” means nothing is entered in profile YAML for that check. The app compares device output with a built-in rule in Application\data\checks. Do not edit check YAML for ordinary site setup. For example, the ACL deny logging check examines every deny statement in interface-bound IPv4 ACLs and requires log-input on the deny statement; log-input is a device configuration keyword, not a YAML value. “Manual review” requires separate evidence.

After a run, use TXT for the original application status and explanation. The app writes Error and Skipped as Not_Reviewed in CKL. Retain redacted evidence and record any manual decision separately.

Important file path: Application\data\profiles\<selected profile>.yaml is beside the EXE in the extracted package. IOS normally uses base_ios_switch_access.yaml; IOS XE normally uses base_iosxe_access.yaml. Edit the profile you actually selected on Audit.

Profile caution: The supplied values are examples from the original installation, including server names and IPs. Replace them with values approved for your site before a live assessment.

Three worked examples

One string - IOS XE: Open Application\data\profiles\base_iosxe_access.yaml. Find management_access: and its acl_name: line. Replace the text after acl_name: with the exact approved ACL name used on the switch. This is an example of the YAML position, not a value to use in a live audit:

management_access:
  acl_name: EXAMPLE-MGMT-ACL

Several strings - IOS: Open Application\data\profiles\base_ios_switch_access.yaml. Under variables:, find logging_servers:. Put each approved logging host on its own indented hyphen line. Replace these example names with the exact IP addresses or names after logging host in the site's switch configuration:

variables:
  logging_servers:
    - log-a.example.invalid
    - log-b.example.invalid

No YAML input - ACL deny logging: For IOS XE V-220529 or IOS V-220581, leave the profile alone. The app reads show running-config, finds interface-bound IPv4 ACLs, and looks for log-input on each deny statement. The keyword does not have to be the last token. If the device has no matching deny statements, inspect the ACL scope yourself before accepting the result.
