# Reporting Guide

Reports are generated by `ReportService` from internal or persisted results, so an old run can be exported without rescanning.

## Formats

- TXT and CSV retain the original operator workflows.
- JSON uses explicit `schema_version: 1` and includes audit, device, STIG, results, summary, and evidence references/hashes. It excludes raw configurations by default.
- XLSX contains Executive Summary, Device Summary, All Findings, CAT I, CAT II, CAT III, Manual Review, Errors, and Evidence Index. Tables have filters, frozen headings, widths, and readable styles.
- CKL remains supported for STIG Viewer 2 workflows.
- CKLB import/population/export uses the STIG Viewer 3 JSON field structure and preserves benchmark, asset, status, finding details, and comments.

## Compliance

The executive calculation treats `NotAFinding` as passing and excludes non-evaluated results from any claim of successful validation. Review `Open`, `Not_Reviewed`, `Error`, and `Skipped` independently; do not interpret absence of an automated finding as proof that a manual control passed.

## Evidence references

Reports reference relative evidence paths, artifact IDs, SHA-256 values, and byte lengths. They do not embed every raw running configuration. Use the Evidence page or the run folder for source output and use **Verify Evidence** before relying on historical files.
